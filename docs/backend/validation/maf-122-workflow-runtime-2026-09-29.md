Reprodução: iniciar apenas `tests/backend-validation/compose.yml` com o projeto acima; configurar as duas variáveis PostgreSQL para a conexão de loopback; construir Release; iniciar `tests/backend-validation/start-api.ps1` em janela oculta e executar `maf-session-process-smoke.mjs` antes e após trocar o processo da API, usando `MAF_SMOKE_SESSION_ID` na segunda chamada. Para Wait, executar `workflow-wait-process-restart.mjs start`, encerrar o processo da API enquanto o `waitUntilUtc` ainda está no futuro, confirmar `Pending` no banco, reiniciar a API e executar o modo `poll` com `MAF_SMOKE_EXECUTION_ID`. Os scripts exigem membership sintética de `gateway-real-validation-user` no tenant `admin` do banco de validação. A ordem e os horários acima são os resultados observados, não uma promessa de exatamente uma execução.

Encerramento: os dois workflows, a sessão e a membership sintéticos usados na prova de processo foram removidos do banco isolado. A API e os dois serviços Compose foram parados; os volumes do Compose foram preservados.
